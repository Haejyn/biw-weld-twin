## Introduction

신차 차체 구조가 기존 스폿 용접 라인에서 생산 가능한지를 설계 단계에서 판단하기 위한 디지털 트윈을 구성하였다. 판금 모자형 단면 판재 15장(두께 1.2 mm)과 플랜지 위 스폿 타점 75개로 이루어진 하위 조립품에 대해, KUKA KR210 L150 의 실제 기구학으로 역기구학 · 건/팔 간섭 · 접근 · 후퇴 경로 · 로봇 간 인터록을 계산하고 목표 JPH 별 로봇 대수와 사이클을 산출한다. 전체 시뮬레이션(약 3분)을 대신하는 LightGBM 대리 모델은 학습에 없던 설계 200개에서 못 쏘는 타점 재현율 99.9 %, 정밀도 100 %를 0.05 초에 판정한다. 아울러 기존 라인에 신차를 혼류 투입할 때의 라인 정지와 5년 비용을 공개 단가로 비교하고, 설계안별 STEP 을 내보낸다.

```mermaid

    K --> P["로봇 배정<br/>조합 전수 · 구역 배정"]
    P --> Q["용접 순서<br/>이동 간섭 → 경유"]
    Q --> I["로봇 간 인터록"]
    I --> T["사이클 · 로봇 대수 · 3D"]
    K --> G["설계 변형 1,000개<br/>37.5만 쌍"]
    G --> AI["LightGBM<br/>+ 판재 여유 특징"]
    AI --> S["설계 탐색 1만"]
    S --> C{"시뮬레이터 확정"}
    B --> CAD["STEP · 타점 CSV"]
    T --> L["혼류 라인<br/>SALBP · CP-SAT"]
    L --> Z["정지 · JPH · 5년 비용 (억 원)"]
```

- **로봇:** 후보 5곳 (바닥 3 + 천장 역설치 2) · 역기구학 · 건/팔 간섭 · 접근 · 후퇴 150 mm 경로
- **경로 · 로봇 간:** 타점 사이 이동 간섭 시 대기 자세 경유 · 로봇 간 우선순위 + 구역 예약 인터록
- **AI:** LightGBM + 판재 여유 특징 · SHAP · 라벨 = 시뮬레이터
- **라인:** SALBP 라인밸런싱 · OR-Tools CP-SAT

## 2. Surrogate Manufacturability Assessment

![AI 평가](docs/img/ai_eval.png)
<sub>그림 2. (a) 학습에 없던 설계 200개 시험 — 좌표만 vs 판재 여유 특징 추가 (b) '못 쏜다' 판정에 기여한 특징 (SHAP)</sub>

| 지표 (시험 200 설계) | 좌표만 | 특징 첫 판 | **특징 수정 후** |
|---|---|---|---|
| 못 쏘는 타점 재현율 | 99.4 % | 97.9 % | **99.9 %** |
| 못 쏘는 타점 정밀도 | 80.6 % | 93.4 % | **100 %** |
| 설계 문제 여부 판정 | 98.0 % | 98.0 % | **99.5 %** |
| 못 쏘는 타점 수 정확 | 54.0 % | 91.5 % | **99.5 %** |
| 설계 1개 판정 시간 | | | **0.05 s** (시뮬레이터: 판정만 약 10 s · 배정까지 약 3분) |

- 데이터: 설계 변수 10개 무작위 · 학습 800 설계 (30만 쌍) · 시험 200 설계 (7.5만 쌍) · 라벨 = 시뮬레이터 (접근 경로 포함)
- 특징 첫 판의 결함: 건–부품 여유를 부품 전체 경계 상자로 측정하여, 타점이 상자 안에 있으므로 값이 늘 0이었다. 그 결과 플랜지 9 mm · 벽 높이 137 mm 설계에서 크로스멤버 12점을 "쏠 수 있다"고 확신하였다(20안 중 1안, 12점 오판).
- 수정: 타점이 붙은 판을 제외한 판재 15장까지의 거리, 건 0 / 15 / 30° 기울임별 전극 · 암 · 몸체 여유. 정밀도 93.4 → 100 %.
- 임계값: 검증 설계에서 못 쏘는 타점 재현율 ≥ 95 %.

![제조성 지도](docs/img/ai_map.png)
<sub>그림 3. (a) AI 제조성 지도 (첫 타점 × 실–B필러 간격). 색 = AI 예측 못 쏘는 타점 0 / 1 / 2, 점 = 시뮬레이터 64개 (전부 일치) (b) 5 mm 간격 경계 검사 — 첫 타점 31/31 · 간격 16/17 일치, 화살표 = 불일치</sub>

- 첫 타점 ≥ 75 mm · 실–B필러 간격 ≥ 45 mm 이면 못 쏘는 타점 0개 (5 mm 간격 시뮬레이터 확인).
- 플랜지 폭 × 벽 높이 상호작용: 벽 120 mm 에서는 플랜지 8 mm 도 문제없음. 벽 137 mm 이상 + 플랜지 9 mm 이면 크로스멤버 12~13점 전부 건 간섭. 둘 중 하나만 되돌려도 0.
- 설계 탐색: 기준 A 주변 1만 안 · AI 4.7분 (시뮬레이터로는 3코어 약 11시간) · 통과 509안 · A 에서 가장 적게 바꾼 20안 시뮬레이터 재검증 **18/20** (틀린 2안은 경계 바로 옆, 1점 차이).
- 상위 3안 전체 시뮬레이션: 못 쏘는 타점 0 · 0 · 1. 단, B필러 · 크로스멤버 위치가 바뀌어 후보 5곳으로 JPH 60 을 맞추지 못함.
- 결론: AI 는 1차 선별에 사용하고, 경계 근처와 사이클은 시뮬레이터가 확정한다.

## 6. AI 설계 수정 에이전트

못 쏘는 타점이 있는 설계와 한국어 제약을 받아, 제약을 지키면서 가장 적게 바꾼 수정안을 찾는다. LLM(Ollama `qwen3.5:4b`)이 도구를 불러 조사하고, 시뮬레이터가 확인한 설계만 제출할 수 있다. 코드는 `src/agent.py`, 평가는 `scripts/agent_eval.py`, 평가 기록은 [`docs/agent_eval.md`](docs/agent_eval.md).

| LLM 이 정하는 것 | 코드가 강제하는 것 |
|---|---|
| 요청 문장을 제약 JSON 으로 옮김 (변수별 고정 / 최소 / 최대) | 제약을 변수 범위(`dataset.SPACE`)와 대조해 검증. 범위 밖 값이나 없는 변수는 거부, 해석한 제약은 출력에 그대로 표시 |
| 어떤 도구를 어떤 설계로 부를지 (`search` 후보 중 무엇을 `simulate` 할지, `simulate` 실패 이유 설명) | `predict` · `sensitivity` · `simulate` 는 인자를 제약과 범위 안으로 잘라서 쓰고, 고정 변수는 시작값으로 되돌림. `submit` 은 자르지 않고 거부 |
| 어느 변수를 얼마나 바꿀지 | 도구 호출 12회, `simulate` 4회 한도. 넘으면 "실패: 한도 초과" 와 시뮬레이션한 것 중 가장 나은 설계를 돌려줌 |
| 언제 제출할지, 근거 문장 | `submit` 승인 조건: 가장 최근 `simulate` 가 바로 이 설계였고, 못 쏘는 타점이 0개이고, 제약을 모두 지킴 |

| 도구 | 하는 일 | 비용 |
|---|---|---|
| `search(design, k)` | 제약을 만족하는 후보를 대리 모델로 훑어 시작 설계에 가까운 k개와 예측 못 쏘는 타점 수를 돌려줌 (국소 탐색 + 전역 후보, 예측 캐시) | 처음 약 25 s, 같은 설계는 캐시 |
| `predict(design)` | 대리 모델이 예측한 못 쏘는 타점 id 와 쏠 수 있을 확률 | 약 0.05 s |
| `sensitivity(design, var)` | 한 변수를 허용 범위에서 9점 훑었을 때 예측 못 쏘는 타점 수 | 약 0.5 s |
| `simulate(design)` | 시뮬레이터 판정. 타점별 실패 이유(도달 불가 · 관절 한계 · 건 간섭 · 팔 간섭 · 접근 경로 간섭) | 약 15 s, 4회 |
| `submit(design, rationale)` | 위 조건을 만족하면 최종안으로 승인, 아니면 문제 목록 | 즉시 |

모든 호출은 도구, 인자, 결과 요약, 걸린 시간(ms)과 함께 trace 로 남는다. LLM 호출 함수는 바꿔 끼울 수 있어 `tests/test_agent.py` 는 Ollama 없이 가짜 LLM 으로 돈다.

```
python -m src.agent --design A --request "못 쏘는 타점이 없게 최소한만 고쳐줘"
python -m src.agent --design C --request "플랜지 폭은 그대로, 첫 타점 거리는 60 이하"
```

`--design` 은 `A` · `B` · `C` 또는 mm 단위 JSON(빠진 변수는 A 값). trace 는 `results/agent_trace_last.json` 에 저장된다.

예: 설계 A, 요청 "플랜지 폭은 그대로, 첫 타점 거리는 60 이하"

```
해석한 제약: 플랜지 폭(flange_width) = 15 고정, 첫 타점 거리(member_first_spot) <= 60
 1. search      후보 5개 (훑은 1807개, 예측 0개 5개) 첫 후보 {'member_first_spot': 38.7, 'member_y0': 154.1, 'sill_pillar_gap': 44.9} 예측 0개 거리 0.284  (25096 ms)
 2. simulate    시뮬레이션 못 쏘는 타점 0개 {}  (17029 ms)
 3. submit      제출 승인
결과: 성공 · member_first_spot 30->38.7, member_y0 120->154.1, sill_pillar_gap 30->44.9 (mm) · 변경 거리 0.284 · simulate 1회 · 61.9 s
```

`search` 를 넣기 전에는 같은 요청이 도구 호출 12회를 다 쓰고 "실패: 한도 초과" 로 끝났다 (12번째 호출에서 0개인 설계를 확인했지만 `submit` 을 부를 호출이 없었다).

평가 결과. 시작 설계 12개(시험 설계 10 + 설계 A, B) × 조건 2. 기준선은 `explore.py` 방식을 시작 설계마다 적용한 것이고, "기준선 + 국소 탐색" 은 `search` 와 같은 국소 탐색 후보를 기준선에도 더한 것이다. 전체 표와 한계는 [`docs/agent_eval.md`](docs/agent_eval.md).

조건 1 (제약 없음)

| 항목 | 에이전트 (search 추가) | 에이전트 이전 (search 도구 없음) | 기준선 이전 | 기준선 + 국소 탐색 |
|---|---|---|---|---|
| 성공 | 12/12 (100 %) | 8/12 (67 %) | 12/12 (100 %) | 12/12 (100 %) |
| 시뮬레이터 호출 (평균 / 중앙값) | 1.8 / 2 | 2.6 / 2 | 1.3 / 1 | 3.0 / 3 |
| 걸린 시간 (평균 / 중앙값, 초) | 66 / 63 | 86 / 57 | 1079 / 1081 | 1368 / 1378 |
| 변경 거리 (성공한 실행의 중앙값) | 0.336 (n=12) | 0.434 (n=8) | 0.448 (n=12) | 0.316 (n=12) |

조건 2 (기준선이 가장 많이 바꾼 변수 하나를 고정)

| 항목 | 에이전트 (search 추가) | 에이전트 이전 (search 도구 없음) | 기준선 이전 | 기준선 + 국소 탐색 |
|---|---|---|---|---|
| 성공 | 3/12 (25 %) | 1/12 (8 %) | 4/12 (33 %) | 4/12 (33 %) |
| 시뮬레이터 호출 (평균 / 중앙값) | 3.1 / 4 | 2.3 / 2 | 0.4 / 0 | 1.0 / 0 |
| 걸린 시간 (평균 / 중앙값, 초) | 133 / 147 | 111 / 108 | 977 / 975 | 1277 / 1272 |
| 변경 거리 (성공한 실행의 중앙값) | 0.379 (n=3) | 0.104 (n=1) | 0.463 (n=4) | 0.337 (n=4) |

- 이번 실행은 이 평가만 단독으로 돌려 전체 3049 s 가 걸렸다 (기준선 국소 탐색 658 s, 에이전트 2389 s).
- 조건 2 의 실패 9건 중 8건은 도구 호출 한도 소진이다. 기준선도 국소 탐색을 더해 새로 찾은 설계가 없었고(성공 4/12 그대로), 두 방식이 모두 실패한 8건은 이 샘플링으로 해를 찾지 못했다는 뜻이며 해가 없다는 증거는 아니다.
- 기준선 시간은 후보 10,000개를 대리 모델에 넣는 단계가 대부분이고 작업자 12개를 동시에 돌려 잰 값이다. 에이전트 시간은 LLM 응답 대기를 포함한다.
- 시뮬레이터 호출은 대리 모델이 0개로 본 후보가 실제로는 1개 남는 경우(설계 A, 조건 2)에 늘어난다. `search` 가 시작 설계에 가까운 순으로 돌려주기 때문에 후보가 경계 근처에 모인다.

## Limitations

- 인터록: 우선순위 + 남은 경로 예약 방식으로 안전하지만 보수적이다. 실제 라인은 구역 신호가 더 세밀하다.
- 사이클: 관절 최대속도 × 가감속 보정 근사이며, 경로는 관절 공간 직선이다.
- 차체: 하위 조립품 1개를 판금으로 단순화하였다. AI 는 이 설계 공간 안에서만 검증되었다.
- 비용: 수동 스테이션 단가와 신규 라인 몫은 가정이므로 경계값으로 읽어야 한다.

## Getting Started

### Installation

```
python -m venv .venv && .venv\Scripts\pip install -r requirements.txt
.venv\Scripts\python src\fetch_data.py         # SALBP 벤치마크 (저장소에 없음)
```

### Running

```
cd src
..\.venv\Scripts\python stage1.py              # 설계안 A/B/C · JPH 별 로봇 (단일 프로세스, 약 30분)
..\.venv\Scripts\python stage2.py              # 혼류 대안 · 비용
..\.venv\Scripts\python dataset.py 800 3 0 && ..\.venv\Scripts\python dataset.py 200 3 1   # 작업자 3개, 약 1시간
..\.venv\Scripts\python surrogate.py           # AI 학습 · 시험
..\.venv\Scripts\python explore.py             # 지도 · 경계 · 탐색 · 전체 시뮬레이션 확정 (약 25분)
..\.venv\Scripts\python export_twin.py && ..\.venv\Scripts\python export_cad.py
cd .. && .venv\Scripts\python scripts\make_readme_figures.py
.venv\Scripts\python -m src.agent --design A --request "못 쏘는 타점이 없게 최소한만 고쳐줘"   # 설계 수정 에이전트 (Ollama 필요)
.venv\Scripts\python scripts\agent_eval.py   # 에이전트 평가 (수 시간, Ollama 필요)
```

디지털 트윈 뷰어는 `open_viewer.cmd` 로 연다.
